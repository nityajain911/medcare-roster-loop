How it works

What's real, what's simulated, and what's assumed.

Real code

NPI check digit, duplicate and required-field checks, the date window, routing, the diff by clinician and site, reconciliation, corrections, roles and every metric.

Simulated Simulated

AI column mapping and email reading, the provider registry (a test list, not NPPES), the provider database and directory, and the directory's specialty codes (a NUCC subset).

Destinations

The pilot has one: the plan's provider database, which feeds the directory. Claims and prior auth come later.

Channels and roles

Portal, roster file (upload or SFTP drop, same pipeline) and email today; CAQH and Availity later. Practice admins send changes. Plan approvers decide them.

Assumptions

15 minutes saved per change, 3 per confirmation. 60-day back-date window.

Target (commercial rule)

Directory updated within 2 business days.

Not in scope

Credentialing, contracting, claims and prior auth decisions. No patient data. NPIs start with 9, so none are real.
